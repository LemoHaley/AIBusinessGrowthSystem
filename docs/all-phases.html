阶段 3：鉴权模块

对应 plan.md 任务 1.5（第 5.4、5.5 节）

未开始 前置：阶段 2 提交：feat: 阶段3 认证鉴权与RBAC

目标

双端登录（小程序微信 + 后台账号密码）、token 签发/刷新/吊销、RBAC 角色守卫。

任务分解

3.1 auth.jwt.ts

  • issueTokens：access 2h（含 type: 'access'）；refresh 7d（type: 'refresh'，防混用）
  • refresh 写 Redis auth:refresh:{userId} EX 7 天（登出即删，支持强制下线）
  • verifyAccessToken：校验签名 + type

3.2 小程序登录 POST /api/auth/wx-login

  • code2session（WX_APPID / WX_SECRET）换 openid
  • 查/建 user（role=parent，uk_tenant_openid 幂等）→ 签发 token

3.3 后台登录 POST /api/auth/admin-login

  • 账号密码 bcrypt verify，仅 admin / teacher 角色可登录

3.4 刷新与登出

  • POST /api/auth/refresh：校验 refresh 有效且与 Redis 值一致（不一致即已吊销/被替换）→ 重新签发
  • POST /api/auth/logout：删 Redis key；GET /api/auth/me：当前用户信息

3.5 RBAC 守卫（第 5.4 节）

  • requireRole(min)：角色等级 admin(3) > teacher(2) > parent(1)
  • 未登录 40001；等级不足 40003

验证清单

  • admin-login 返回 access + refresh
  • /api/auth/me 带 token 正常；错 token 返回 40001
  • parent 角色访问 teacher 级接口返回 40003
  • logout 后旧 refresh 调 /refresh 失败
  • Redis 中可查到 auth:refresh:{userId}

阶段 4：积分核心

对应 plan.md 任务 2.3-2.5（第 7 节）

未开始 前置：阶段 2 凭证：本地 Redis 即可 提交：feat: 阶段4 积分账本核心

目标

积分账本核心闭环：Lua 原子扣减（防超发）、余额缓存预热（防误判 0）、失败回滚、定时对账、充值与计价接口。本阶段全部本地可验证，不依赖 AI 服务。

任务分解

4.1 Lua 脚本 scripts/lua/deduct_points.lua（第 7.2 节）

  • KEYS[1] = points:balance:{tenantId}:{userId}；KEYS[2] = points:lock:{bizId}
  • EXISTS 幂等锁（返回 -2 重复）→ 余额校验（-1 不足）→ DECRBY + SET lock EX 300

4.2 points.service.ts（第 7.3 节）

  • ensureBalanceLoaded：key 不存在时从 point_accounts 加载，SET NX 写入（防覆盖并发充值）
  • deductPoints：先预热再 redis.eval 执行 Lua
  • rollbackPoints：INCRBY 回滚 + rollback 反向流水（bizId = rollback:{原bizId}，不改原流水）

4.3 BullMQ 对账任务（每 1 分钟，第 7.5 节）

  • SCAN MATCH points:balance:* 游标遍历（禁止 KEYS）
  • 以流水聚合为准：不一致修复 Redis + 告警日志；upsert point_accounts

4.4 积分接口（第 8.5 节）

MethodPath说明角色
GET/api/points/balance查询机构积分余额teacher
POST/api/points/recharge充值（INCRBY + recharge 流水）admin
GET/api/points/ledger流水查询（分页）teacher
GET/api/points/prices计费单价teacher
POST/api/points/prices/update更新计费单价admin

验证清单

  • 100 并发同额扣减：终值 = 初值 - 100 x 单价，无超发
  • 同 bizId 重复请求返回 40902（幂等锁生效）
  • 余额不足返回 40901
  • 删 Redis 余额 key 后扣减：预热生效，不误判为 0
  • 先扣后回滚：rollback 流水生成，余额恢复
  • 对账任务运行后 MySQL 与 Redis 一致

阶段 5：AI 中台

对应 plan.md 任务 2.1、2.2（第 6 节）

未开始 前置：阶段 4 凭证：Coze API key + bot id 提交：feat: 阶段5 AI中台与SSE流式输出

目标

Provider 抽象（第三方可插拔）+ Coze 接入 + SSE 流式输出 + 计费闭环（扣减 → 生成 → 失败回滚）。

任务分解

5.1 Provider 抽象与 Coze 实现

  • provider.interface.ts：AiProvider（chat + chatStream）、AiChatParams、AiResult
  • CozeProvider（首选）：对接 Coze chat API，支持流式
  • 预留 DifyProvider / OpenAIProvider 扩展位（本阶段只做 Coze）
  • 读 agent_configs 按 agentType 路由 provider/bot_id（租户配置优先，0 为全局默认），在线切换无需发版

5.2 SSE 封装 modules/ai/sse.ts（第 6.2 节）

  • 响应头：text/event-stream、no-cache、X-Accel-Buffering: no
  • 心跳：每 15s 写 : ping 防断连；数据事件 data: { type: 'chunk', content }
  • 结束 event: done；异常 event: error；finally 清理定时器

5.3 AI 接口（第 8.3 节）

MethodPath说明角色
POST/api/ai/chatSSE 流式；stream=false 非流式teacher
POST/api/ai/report/generate生成点评/报告（body 含 bizId）teacher
POST/api/ai/copywriting/generate生成招生文案（body 含 bizId）teacher
GET/api/ai/logs调用日志（分页/筛选）admin
GET/api/ai/agentsAgent 配置列表admin
POST/api/ai/agents/update更新配置admin
bizId 规则：由前端生成（nanoid/uuid）随请求体传入，服务端不得自行生成——同一 bizId 重试只扣一次积分。

5.4 计费闭环（第 6.4 节时序）

  1. 查 point_prices 得单价
  2. deductPoints(bizId)：不足 40901 / 重复 40902 直接返回
  3. 调 provider；成功：事务写 ai_logs + ai_reports
  4. 失败：rollbackPoints 回滚余额 + 写 rollback 流水

验证清单

  • curl -N 流式收到多个 chunk + done 事件
  • stream=false 返回完整 JSON
  • Coze key 配错时：积分自动回滚 + rollback 流水
  • 重复 bizId 返回 40902，不重复扣费
  • ai_logs 记录 tokens / cost_points / duration_ms
  • 后台改 agent_configs 无需重启即生效
